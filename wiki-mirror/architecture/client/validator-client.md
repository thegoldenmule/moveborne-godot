# Validator Client

**Status:** current

## Kind
subsystem

## Summary
net/hermes_client.gd (MbHermesClient) — the validator client over the Snapser Hermes WebSocket envelope: binary protobuf ClientMessage/ServerMessage frames over Godot's WebSocketPeer, with godobuf-generated bindings in net/proto/. Sends the moveborne.validator.v1 RPCs (InitMatch, ValidateAction, CompleteMatch) as MESSAGE_TYPE_SNAP_API_PROXY snap_api_requests correlated by mid, and surfaces match / authoritative-state-sync results to the Match Controller. Replaced the hand-rolled Engine.IO/Socket.IO client (net/validator_client.gd, retired).

## Purpose
One codepath for both targets — only the URL differs: locally the validator's Hermes-emulation endpoint (ws://localhost:5555/hermes/ws?token=<player-id>, token = self-stamped player id), deployed the real gateway Hermes (wss://gateway.snapser.com/<snapend>/v1/hermes/ws?token=<session>). Token-in-query auth is what makes web exports work (browsers cannot set WS upgrade headers — the bug that killed the old Socket.IO path). On match it confirms the optimistic move; on mismatch it returns the validator's authoritative state for the controller to snap to; CompleteMatch settles rewards on quit.

## Data model
Bindings generated by the vendored godobuf addon (addons/godobuf) from validator/protos/ into net/proto/{hermes_envelope_pb.gd, validator_pb.gd} — regenerate per net/proto/README.md when protos change; never edit by hand. Game state/actions travel as canonical-JSON strings inside proto fields (the determinism hash domain).

## Usage
Activated by the V key for local dev (main.gd LOCAL_VALIDATOR_WS) or automatically for Story/PvP after anonymous Snapser sign-in (main.gd SNAPSER_HERMES_WS + MbSnapserAuth session token). The HUD reflects status as validator: ✓ move N. Headless E2E: tools/test_validator_client.gd (local: init → match → forced mismatch → complete) and tools/test_snapser_client.gd (real gateway). Byte parity of the bindings vs the TS encoder: tools/verify_hermes_proto.gd. Do NOT send Message_Ping to live Hermes — it drops the connection.

## Invariants & constraints
- The predicted hash sent up is exactly the hash MbEngine produced for the optimistic move — same canonical serialization as the validator, or every move would falsely mismatch.
