# Generated protobuf bindings (godobuf)

GDScript bindings for the validator wire protocol, generated by the vendored
[godobuf](https://github.com/oniksan/godobuf) addon (`addons/godobuf/`) from
the proto sources in `../../../validator/protos/` — the single source of truth
for every message that crosses the game ⇄ validator boundary.

| File | Source proto |
|---|---|
| `hermes_envelope_pb.gd` | `validator/protos/hermes/hermes_envelope.proto` (Snapser Hermes ClientMessage/ServerMessage envelope) |
| `validator_pb.gd` | `validator/protos/moveborne/validator/v1/validator_messages.proto` (InitMatch/ValidateAction/CompleteMatch messages) |

**Do not edit the `*_pb.gd` files by hand.** After changing a proto, regenerate
(from the repo root; `--input` must be an OS path, not `res://`):

```bash
/Applications/Godot.app/Contents/MacOS/Godot --headless --path game \
  -s res://addons/godobuf/godobuf_cmdln.gd \
  --input=$PWD/validator/protos/hermes/hermes_envelope.proto \
  --output=res://net/proto/hermes_envelope_pb.gd

/Applications/Godot.app/Contents/MacOS/Godot --headless --path game \
  -s res://addons/godobuf/godobuf_cmdln.gd \
  --input=$PWD/validator/protos/moveborne/validator/v1/validator_messages.proto \
  --output=res://net/proto/validator_pb.gd
```

godobuf quirks the protos already account for (see comments in the sources):
no `service` blocks (hence the messages/service file split), no field named
`message`, no apostrophes in comments, and proto `package` statements are
ignored (flat scope per generated file). Codegen exits 0 even on failure —
check the output for `Compiled ... to ...`.
