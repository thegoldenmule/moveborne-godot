# Feature: ArtGen — Recraft Asset Generation

**Status:** shipped

## Summary
Generate 2D assets (bottom-bar UI icons first; tarot card art later) in the **occult-arcade** style from inside the Godot editor, against the **Recraft** API — iterable by a human in a bottom-panel dock *and* drivable by Claude over MCP. Every generation ever made is recorded in a committed append-only ledger and stays browsable (Recraft itself keeps nothing); promoting a generation is an explicit **save** that copies the file into `res://assets/generated/`, triggers import, and records AI attribution in a central manifest (`ai_manifest.json`). Style consistency comes from a one-time Recraft custom style built from curated `art/` reference crops plus per-request palette controls (violet `#A100FF` on black). Provider research (2026-06-09) ranked Recraft over Leonardo.ai, gpt-image-1.5, and Scenario for this use case (persistent style_id, native SVG, sync JSON API). Status: **proposed** — nothing built; first step is the ~$1 M0 API spike.

## Components affected
- game/addons/artgen — @tool EditorPlugin (lifecycle, bottom panel, bridge startup)
- artgen_service.gd — UI-free core: request queue, ledger, manifest, save pipeline; emits signals so the dock refreshes on MCP-triggered work
- recraft_client.gd — Recraft REST client (generate, create_style, list_styles, removeBackground, me); one in-tree HTTPRequest per call, serial queue, 120 s timeout
- multipart.gd — hand-rolled multipart/form-data builder (style creation + removeBackground uploads via request_raw)
- bridge.gd — localhost HTTP server (TCPServer :4848, env ARTGEN_BRIDGE_PORT) exposing the service to the MCP shim; holds connections open through 10–60 s generations
- Dock UI — compose (preset/prompt/variations/advanced), gallery over the full ledger with filters, detail view (save / iterate / more variations / discard, black-vs-checkerboard preview), settings (API key, style management, balance)
- tools/artgen_mcp.ts — zero-dependency Bun stdio MCP shim registered in .mcp.json as 'artgen' (tools: artgen_status, artgen_generate, artgen_history, artgen_get, artgen_save, artgen_discard, artgen_style_create)
- art/generated/ + ledger.jsonl — committed append-only history of every generation (image files bucketed by month; thumbnail cache gitignored)
- res://assets/generated/ + ai_manifest.json — promoted assets + central AI-attribution manifest (generator, style_id, prompt, gen_id, sha256)
- art/style_refs/ — curated 1024² reference crops (≤5 files, ≤5 MB total) for Recraft custom-style creation
- presets.json + config.json — committed prompt presets encoding the style guide (icon-flat, icon-raster, card-glyph, card-illustrated, texture) and model/style pins

## Design constraints
1. Recraft is stateless: no history/list endpoint, and generated-image URLs expire after ~24 h — request b64_json and write files locally immediately; the committed ledger is the only durable history.
2. Custom style_id works only on V3 models (recraftv3 / recraftv3_vector); V4/V4.1 reject styles and recraftv4_1 is the API default — models must be pinned in config, never defaulted.
3. style (named curated style) and style_id are mutually exclusive in one request; controls.colors / controls.background_color work on all models and force the violet-on-black palette.
4. godot-ai's MCP tool list is defined in its external PyPI package (tool_catalog.gd is a CI-enforced mirror; handlers hard-registered in its plugin.gd; no project-side hook) — ArtGen cannot extend it without forking, so it ships its own MCP entry point, matching the repo's validator/wiki pattern.
5. API key is never committed: EditorSettings project metadata (gitignored res://.godot/editor/project_metadata.cfg) with RECRAFT_API_KEY env fallback; only the editor talks to Recraft — the MCP shim never holds the key.
6. Style guide: icons are flat violet (#A100FF) line-art on black with no gradients or baked glow — glow is applied in-engine; presets must encode this ('no gradients, no glow, no shading').
7. Generation history lives outside res:// (art/generated/) so hundreds of experiments do not churn the Godot importer; only explicitly saved assets enter the project.
8. Invariant: every file under res://assets/generated/ (except the manifest itself) has an ai_manifest.json entry; sha256 detects post-save hand edits (flagged, not blocked).
9. The MCP path requires the editor to be open (the bridge runs in the editor process); the shim must return a clear 'editor offline — open game/ in Godot' error otherwise.
10. No transparency at generation time on Recraft — transparency comes from SVG background-rect stripping or the removeBackground endpoint ($0.01); HTTPRequest nodes must be in the editor tree; serial queue stays far under rate limits (5 req/s, 100 img/min).

## Resolved questions
1. **Claude must be able to drive generation over MCP ('over the godot mcp'). Extend the bundled godot-ai server, or ship a separate entry point?** — _Ship ArtGen's own MCP entry point: a zero-dependency Bun stdio shim (tools/artgen_mcp.ts) proxying a localhost HTTP bridge (:4848) inside the editor plugin. godot-ai's tool surface is defined in its external PyPI package (tool_catalog.gd is a CI-enforced mirror; no project-side registration hook), so extending it means forking a third-party package. Matches the repo's validator/wiki purpose-specific-MCP pattern; handlers still run in the editor process. See the sealed Spec decision._
2. **How do we track everything ever generated so past work stays browsable, given the provider may not store it?** — _It does not: Recraft has no history endpoint and image URLs expire after ~24 h (verified against the live OpenAPI spec). So: request b64_json, write every image immediately to art/generated/<YYYY-MM>/, and journal everything in append-only ledger.jsonl (generation/save/discard/style_created events, full prompt+params+cost, parent_id lineage), committed to git._
3. **Where should generation history live — inside res:// or outside the Godot project?** — _Outside res://, at repo-root art/generated/ — keeps hundreds of experiments out of the Godot importer (no .import churn or scan cost); the editor reads previews via absolute paths. Only explicitly promoted assets enter res://assets/generated/. Both stores are committed._
4. **How is a saved asset attributed to AI for audits and store disclosure questionnaires?** — _Central committed manifest res://assets/generated/ai_manifest.json keyed by res path: generator/model, style_id, full prompt, gen_id, timestamps, sha256, post-processing. Invariant: every file in that folder has an entry; sha256 flags post-save hand edits (modified_after_save, not blocked). Doubles as the store AI-disclosure record._
5. **Vector SVG or raster PNG for icons, and how is transparency achieved?** — _Vector-first: recraftv3_vector at 1:1 — real SVG, crisp at any scale; transparency by stripping the full-canvas background rect (validated in M0). Fallback preset: recraftv3 raster 1024x1024 + removeBackground ($0.01). Glow is never baked — style guide mandates flat line-art with glow applied in-engine; gpt-image-1.5 stays the researched fallback for painterly baked-alpha card art._
6. **Does a Recraft custom style built from ≤5 reference crops capture the occult-arcade look well enough to beat the fallback (curated 'Line art' style + color controls + strong prompt)? Resolve in the M0 spike.** — _Resolved in M0 (2026-06-10, ~860 credits total): YES, decisively — with one wrinkle. The 'Line art' named fallback bakes <linearGradient> defs into its SVGs (violating the no-gradients style rule) and reads soft/illustrative; rejected. A custom style from the original card-dominated crops captures the palette/line perfectly but biases every output toward ornamental card frames, even with 'bare glyph, no frame' prompts. Fix: TWO custom styles — icons 19f7542f-0727-4f6f-9d07-728c439fc583 from frameless glyph-sheet refs (art/style_refs/icons/, composed from globe/bolt/sigil/op-art crops; produces clean bare centered glyphs) and cards 89aedef2-2411-42fc-aa8b-aec391b51bc7 from the card crops (art/style_refs/). config.json pins the icon style as default style_id; card presets override per-preset in presets.json. Side-by-side evidence committed under art/generated/2026-06/ + ledger.jsonl._
7. **Do Recraft-generated SVGs bake in a full-canvas background rect, and does Godot's ThorVG importer handle them cleanly? Resolve in the M0 spike.** — _Resolved in M0 with real output: YES — Recraft vector SVGs carry a full-canvas background as their FIRST <path> (a polygon 'M 0 0 L W 0 L W H L 0 H z', not a <rect>; sometimes with extra collinear edge vertices, and occasionally filled with the ACCENT color when the composition inverts — so stripping must be fill-guarded). Strip rule implemented in game/addons/artgen/svg_tools.gd: remove the first path iff every vertex lies on the viewBox border, all 4 corners are covered, and fill matches the requested background color; otherwise return background_fill_mismatch. ThorVG: all 10 committed M0 SVGs parse via Image.load_svg_from_string, and the editor importer produces a CompressedTexture2D 1024² with corner alpha 0.000 after strip. Verifier: game/tools/verify_artgen_svg.gd → PASS. Default preset pinned: icon-flat = recraftv3_vector + icon style + strip_bg_rect; icon-raster (recraftv3 + removeBackground) kept as fallback preset._
8. **Need a Recraft API token (app.recraft.ai/profile/api) with a small prepaid balance (~$1–5) before the M0 spike can run.** — _Provided 2026-06-10: RECRAFT_API_KEY lives in the gitignored repo-root .env (with a committed .env.example placeholder). Validated live against GET /v1/users/me — account benjamin@thegoldenmule.com, 5000 credits prepaid (raster gen ≈40 units, vector ≈80, style creation ≈40 — ample for M0). Editor tooling reads it via the env fallback; EditorSettings storage arrives with M1._
9. **Finalize the save category list (icons / cards / textures / misc) and decide whether to add a tools/ check script enforcing the manifest invariant — decide by M1.** — _Decided in M1: save categories finalized as icons / cards / textures / misc (ArtgenService.SAVE_CATEGORIES, mirrored in the artgen_save tool's enum). No separate tools/ check script — the manifest invariant is enforced by ArtgenService.check_manifest() (re-hashes every promoted asset, flags hand-edits as modified_after_save, reports files missing entries), exposed via the dock Settings button; verified in the e2e + hand-edit tests 2026-06-10._
10. **Reviewer checklist before ship (built + machine-verified 2026-06-10; commits d8a5ebd/328debc/6387f75): (1) restart the Godot editor — the ArtGen bottom panel appears (plugin enabled in project.godot); do one interactive pass: compose icon-flat → Generate → detail preview black/checkerboard → Save → gallery refresh (covers the two open dock test cases). (2) approve the new 'artgen' MCP server when Claude Code prompts on next session (adding it to .claude/settings.local.json was permission-gated for the agent; .mcp.json registration is committed). (3) Open testing cases left unflipped on purpose: Generate-dock + MCP-loop dock-refresh (need eyes on the editor) and 6-deep queue editor-freeze feel (queue mechanics verified headless). The error-paths case passed after its zero-balance clause was removed as untestable (2026-06-10). (4) Known cleanups, non-blocking: config.fallback_style is documentation-only (no auto-fallback code path — M0 rejected 'Line art'); svg strip rule matches Recraft's current fill="rgb(r,g,b)" form and returns a safe no_background status if the format ever drifts.** — _Reviewer (Benjamin) completed the checklist 2026-06-10 and approved: dock interactive pass good, remaining test cases checked off (all 13 passed), feature signed off for review/ship._
