# Feature: Editor Tool Framework — shared base for in-editor authoring tools (migrate ArtGen + Story Map)

**Status:** building

## Summary
Extract the common skeleton that ArtGen and Story Map both reinvent into a small, editor-only shared framework — `game/addons/editor_tool_kit/` — then migrate both tools onto it with **zero behavior change**. The framework is five primitives drawn from what ArtGen already proves in production: **`EditorToolPlugin`** (collapses the ~25–37 line `plugin.gd` bootstrap + bottom-panel mount/teardown), **`ToolService`** (a `Node` base owning state + signals, every method returning `{ok, error}`, with no `Control`/`EditorInterface` deps so it runs headless), **`ContentStore`** (load → validate → atomic N-target write → `fs.scan()`, with dirty tracking, version-bump rollback, and canonical serialization — generalizing Story Map's hand-written baked+canonical+layout save), **`EditorToolUi`** (the `HSplitContainer`-with-floors layout, `label_wrap`/row builders, selection restyle, and one-line status `Label` both docks rebuild), and an optional **`BridgeServer`** (`TCPServer` poll loop + `Content-Length` framing + async route table + headless-skip, generalized from ArtGen's `:4848` bridge). **ArtGen** migrates by re-basing its plugin/service/bridge on the new bases and deleting the per-tool copies (it already conforms to ~80%). **Story Map** is the bigger lift and the real prize: its monolithic 1,000-line dock splits into a headless-testable `StoryMapService(ToolService)` + a thin view, with `catalog_edit.gd`'s serialize + 3-file atomic save moving behind `ContentStore`. Net result: persistence, layout, status, and optional MCP/CLI access are inherited, every tool's logic becomes headless-verifiable, and the next authoring tool is a service + a view. See the *Editor Tool Framework* architecture node for the target structure. Output files, ArtGen's bridge port + MCP surface, and Story Map's validator-content sync all stay byte-identical.

## Components affected
- game/addons/editor_tool_kit/ — NEW editor-only shared addon (enabled in project.godot [editor_plugins] only as a library; never imported by the running game or game/logic/). Houses the five primitives below + a README.
- EditorToolPlugin (editor_tool_kit/editor_tool_plugin.gd) — EditorPlugin base. A subclass overrides _config() -> {panel, service, dock, bridge?}; the base constructs the service (+ optional bridge), injects it into both, mounts the dock via add_control_to_bottom_panel, and reverses everything in _exit_tree. Replaces artgen/plugin.gd and story_map_editor/plugin.gd.
- ToolService (editor_tool_kit/tool_service.gd) — Node base: state owner + signal emitter, with ok()/err() helpers enforcing the {ok, error, ...} return contract and a _dirty flag. ZERO Control/EditorInterface deps so it runs under godot --headless. artgen_service.gd re-bases onto it; a NEW StoryMapService is extracted from story_map_editor/dock.gd onto it.
- ContentStore (editor_tool_kit/content_store.gd) — static helper for load → validate → atomic N-target write → EditorInterface rescan: default-{} on missing, dirty tracking, save-time version bump with rollback on any write failure, and canonical JSON serialization (stable key order + integer coercion + sparse fields). Generalizes Story Map's baked+canonical+layout 3-file save; catalog_edit.gd's serialize() is the reference impl.
- EditorToolUi (editor_tool_kit/editor_tool_ui.gd) — static layout helpers: HSplitContainer root with min-size floors, label_wrap / form-row builders (label + expanding control), rebuild-form-on-selection, StyleBoxFlat selection restyle, and a status Label driven from {ok, error}. Both docks adopt it incrementally; no visual change.
- BridgeServer (editor_tool_kit/bridge_server.gd) — OPTIONAL Node mixin generalized from artgen/bridge.gd: TCPServer + _process poll loop, Content-Length request framing, an async match [method, path] route table that can await service coroutines, JSON responses, and a headless skip. ArtGen subclasses it (routes -> service methods); Story Map opts out in v1.
- ArtGen migration — re-base artgen/plugin.gd on EditorToolPlugin, artgen_service.gd on ToolService, artgen/bridge.gd on BridgeServer; route dock layout through EditorToolUi where it reduces code. Keep ledger.gd, recraft_client.gd, multipart.gd, svg_tools.gd, config.json, presets.json, the :4848 port + ARTGEN_BRIDGE_PORT override, and the artgen MCP shim surface unchanged. Verify generate/save/swap/history/style-create still work end-to-end.
- Story Map migration — extract StoryMapService(ToolService) from story_map_editor/dock.gd (in-memory catalog/layout, dirty tracking, mutations via catalog_edit.gd, validate, serialize, and the baked+canonical+layout save via ContentStore + the Remote Config verify/clipboard helpers); dock.gd becomes a thin view binding the service + EditorToolUi. Same three output files, byte-identical.
- Headless verifiers + docs — tools/verify_editor_tool_kit.gd (ContentStore atomic/rollback/serialize + ToolService {ok,error}/dirty contracts) and tools/verify_story_map_service.gd (the now-testable Story Map logic: mutations, validate, 3-file serialize parity). Wire both into the verifier list in game/CLAUDE.md / CLAUDE.md commands and record a synced commit on the architecture node.

## Design constraints
1. Behavior parity is the acceptance bar. Both tools must produce byte-identical output files after migration (ArtGen: generated art + ledger.jsonl + ai_manifest.json; Story Map: story_catalog.json baked + validator/content canonical + story_maps.json). No art is regenerated; no catalog re-serialized to a different byte stream. Diff the outputs before/after each migration commit.
2. Additive then incremental: the framework lands FIRST as new editor-only shared code that nothing depends on yet; ArtGen and Story Map then migrate in SEPARATE commits, each independently revertable. No big-bang cutover.
3. The editor/headless seam is strict: ToolService and ContentStore's pure logic carry no Control/EditorInterface deps and run under godot --headless; the editor-only calls (add_control_to_bottom_panel, FileDialog, get_resource_filesystem().scan(), OS.execute for the Remote Config helper) live in the plugin/dock or behind a thin editor-side seam in ContentStore that the headless path skips.
4. BridgeServer is opt-in per tool and a no-op under headless (DisplayServer.get_name() == "headless"), so verifiers and CLI runs never bind a port. ArtGen keeps port 4848, the ARTGEN_BRIDGE_PORT env override, and the config.bridge_port fallback exactly as today.
5. Editor-only, never shipped in the game: editor_tool_kit/ is a tool library, not imported by game/scenes, game/ui, game/net, or game/logic/. It does not affect determinism parity, the validator, or any runtime path — zero parity tests are touched.
6. Mirror existing conventions: pure GDScript, no new dependencies; class_name on the bases; commit .gd.uid files; register via plugin.cfg + project.godot [editor_plugins]; keep dock<->service signal bindings as method callables (not lambdas) for hot-reload safety.
7. Story Map's validator-content sync and Remote Config publish helper keep working: the baked + canonical byte-identical pair becomes a ContentStore N-target write, and the `bun ... story-appconfig.ts verify` / clipboard-export actions move into StoryMapService (shelling out stays editor-side) with identical output.
